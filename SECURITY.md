# Security

- Authentication: Keycloak realm `taskmgr`, client `task-web` (public PKCE) and `task-api` (bearer-only).
- Spring Security OAuth2 resource server validates JWT issuer/JWKS. Production also requires audience `task-api` (Keycloak mapper on `task-web`).
- Authorization: membership roles `ORG_ADMIN`, `PROJECT_MANAGER`, `MEMBER` in PostgreSQL. Mapping from the previous OWNER/ADMIN/VIEWER model is in `docs/adr/0006-rbac-mapping.md`. `SUPER_ADMIN` is a platform flag synced from the Keycloak realm role of the same name; it is not granted via add-member. ORG_ADMIN/PROJECT_MANAGER manage projects. MEMBER may mutate only tasks they created. ORG_ADMIN cannot be assigned via add-member. ORG_ADMIN can change PROJECT_MANAGER/MEMBER roles (`PUT /api/organizations/{id}/members/{userId}`); the audit row stores `old->new`.
- Suspended organizations (`PUT /api/organizations/{id}/status`) block all tenant-scoped member operations. `SUPER_ADMIN` can still operate and unsuspend. Listing organizations is still allowed so the status is visible.
- Inactive local user rows are rejected even if the JWT is valid.
- Cross-tenant access returns 403 or 404 (hidden by organization filter). Authentication failures and authorization denials are logged as `security.auth_failure` / `security.authz_failure` (method, path, correlation id, subject, org header). Tokens and Authorization headers are never logged. Cross-tenant 403s also insert `ACCESS_DENIED` audit rows for the target organization. Audit inserts use `REQUIRES_NEW` so a denial on a read-only query still returns 403 instead of failing with HTTP 500. Invalid bearer tokens return JSON 401 (`Unauthorized`) via the OAuth2 resource-server entry point.
- Task writes: `TASK_CREATED`, `TASK_UPDATED` (metadata `title/status->title/status`), `TASK_DELETED`. Role changes store `old->new`. Suspension stores `ACTIVE->SUSPENDED`.
- Task POST/PUT/DELETE are rate-limited in Redis with an atomic Lua `INCR`+`EXPIRE` (HTTP 429). Redis outage on writes is fail-closed (503) after the Lettuce command timeout (`spring.data.redis.timeout=2s`, applied via `LettuceClientConfigurationBuilderCustomizer`). `GET /health` is process liveness only. `GET /ready` (and Compose healthchecks) consult Postgres + Redis and abort after 3 seconds with HTTP 503 instead of waiting on Lettuce's default 60s command timeout. Dashboard cache reads fail open to Postgres. Idempotency is PostgreSQL-backed and is not skipped when Redis is down — writes never reach create if rate limiting cannot run. See `docs/adr/0009-rate-limit-lua.md`.
- Analytics cache keys are `analytics::org:{id}`. Writes use Redis `SET` with an explicit TTL (`app.analytics-cache-ttl-seconds`, default 60). Cache outage fails open to a live DB compute. Task CUD deletes the org key.
- Idempotency keys are reserved in a separate transaction. Concurrent duplicates wait and replay; stale in-progress rows are reclaimed; completed keys expire after 24h. See `docs/adr/0008-idempotency-wait-replay.md`.
- Audit logs are append-only (insert repository only; no update/delete API). Read access is `ORG_ADMIN` / `SUPER_ADMIN` only. Task C/U/D, member add, role change, org status change, and overdue-scan events are recorded. Rows store `correlationId` (from `X-Request-Id` or a generated UUID) rather than client IP. IP is omitted because Compose sits behind untrusted `X-Forwarded-For` with no configured proxy trust list; collecting spoofable addresses would not be a reliable security signal. Correlation ids are enough to join application logs to a request.
- JWT tests sign/verify RS256 tokens; random/expired/wrong-issuer/wrong-signature tokens are rejected.
- Secrets are environment variables. `.env` and `application-local.properties` are gitignored. `.env.example` contains **placeholders** only. Compose still has local-demo fallbacks `tenant` / `admin` if those variables are unset — override them on any shared host.
- CORS allows only the local UI origins.
- Passwords live in Keycloak, not in the application database.
- Swagger UI and `/v3/api-docs` are **intentionally public** on the local Compose API (`SecurityConfig` permitAll) so assessors can explore endpoints without a SPA session. Do not expose Swagger on a real production internet deployment without authentication.
- Actuator exposure is `health` only. Assessment aliases: `GET /health` (process liveness) and `GET /ready` (readiness group: process + Postgres + Redis in prod, 3s abort → 503). Compose and the image `HEALTHCHECK` call `/ready`. Liveness is also `/actuator/health/liveness`. Unknown routes return JSON 404.
